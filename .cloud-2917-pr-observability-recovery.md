## Summary

Recover durable evidence for the 10 events admitted by the failed-closed #2917 Queue canary before any retry or drain.

The canary reached exact durable admission 10/10 but live tail observed none of the admitted/reservation/outcome records. Production is independently contained; this PR adds a read-only retrospective workflow that queries Cloudflare Workers Logs for the exact canary window and run marker, then queries every recovered admitted identity in memory.

## Safety boundary

- Requires exact restored control HMAC and deployed Worker code-etag HMAC before querying.
- Uses Queue/Worker GETs and Cloudflare's read-only Workers Observability telemetry query POST only.
- No Queue settings, consumer, deployment, D1, DLQ, or Nango mutation endpoint is present in the diagnostic path.
- Fails closed on missing/invalid/truncated query results.
- Raw logs, exact resource identifiers, message identities, and controls are written only as AES-256-GCM evidence with pinned digests.
- Public output contains counts, HMAC-pseudonymized outcome/provider refs, and keyed Worker-version refs only.
- No canary retry, drain, replay, DLQ disposition, purge, or Nango action is performed or authorized.

Cloudflare primary documentation defines this endpoint as a telemetry query over stored Workers Logs and supports dry, bounded event views, exact service filters, and full-text needle search:

- https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/
- https://developers.cloudflare.com/workers/observability/query-builder/
