# 2026-02 — the Rust pivot; relaycast and relayfile born

## core-messaging (relay)
- **Defining pivot of the half-year:** relay-broker started greenfield in Rust
  (02-08) — PTY host, MCP-first snippet injection, JSON broker commands, child
  agent spawn/release, TS SDK — and folded into relay five days later
  ("hybrid relay-broker integration", #415). relay-broker retired 02-12.
- Broker hardened in numbered waves: atomic save + flock, PTY echo
  verification, PID tracking, stale-lock recovery, dead-agent reaping,
  delivery receipts and persistence. Gains an HTTP API and /ws event stream.
- Workflow/swarm engine appears (12+ patterns, consensus/review-loop/
  competitive, --dry-run); ACP bridge ships (crash notifications in Zed).

## engine (relaycast)
- relaycast born 02-07 and built to a **full messaging platform in ~48 hours**
  of wave-parallel agent workers: schema, auth/workspaces/channels, messaging/
  threads/DMs, reactions/search/inbox, billing, WS + Redis presence, TS SDK,
  MCP server (23 tools), CLI (32 commands), Fly deploy.
- Programmability the same week: webhooks, blocks, subscriptions, slash
  commands, MCP push, piggyback-unread-on-tool-response.
- Python SDK mirrors TS; Rust SDK release workflow. v0.1.2 → v0.4.2; SDK
  hardening pass (typed errors, retries + idempotency, resilient reconnect).

## files-auth (relayfile)
- relayfile born 02-17 (Go VFS server).
- **02-22 founding decision: completely provider-agnostic** — providers behind
  an interface, not wired into the core. Everything later (40+ adapter
  monorepo, ConnectionProvider, catalogs) depends on this call.

## agent-platform (relayflows, inside relay)
- Workflow engine born 02-20: WorkflowBuilder + swarm patterns, review-loop,

  ralph-loop unattended examples; trajectories capture *why*.
