## Summary

- resolve each existing Cloudflare Queue consumer through the documented read-only GET-by-consumer endpoint
- keep consumer resource identifiers out of inventory artifacts, console output, workflow comments, and error labels
- accept Queue topology only when main and DLQ each resolve exactly one worker consumer and both point to the same Worker
- report per-queue detail resolution counts so loss of observability remains explicit

## Why

The post-#2956 inventory proved both Queue endpoint/detail views contain one consumer, but Cloudflare's list/detail objects omitted the optional `script_name`. The old snapshot therefore reported a misleading zero-name topology and could not inspect the Worker admission gate or cron. Cloudflare's official Consumer API documents a GET-by-consumer-resource endpoint that can return the Worker response without mutating it.
