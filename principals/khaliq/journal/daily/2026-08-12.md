## Learned

- **CF Queue delivery can pause independently of consumer health.** The every-5-min cron health check was logging `healthy: false, backlogCount: 25572` but the pause state (`delivery_paused: true`) is only visible via CF API queue detail endpoint — wrangler CLI doesn't surface it. Root cause of the pause: unknown (no explicit pause action taken by any human). Suspicion: SST deploy on Aug 3 with `deleteBeforeReplace: true` on the QueueConsumer triggered a brief consumer tear-down, during which CF paused delivery.
- **Factory GitHub-native routing uses source repo, not the readiness label.** `labelRoutesForIssue` filters out `requireLabel` ("factory") from routing candidates for GitHub issues. When no routing labels remain, `githubMirrorRouteForIssue` reads the `source.repo` VFS field and matches it against `byLabel` VALUES — so a relay repo issue routes to relay without a `relay` label. The `factory` label alone is sufficient; adding or removing labels mid-dispatch causes a projection race (`LiveDispatchStateChangedError`).
- **Factory `dispatch <path>` skips `requireLabel` in triage but re-checks in dispatch.** `triageIssue` succeeds without the requireLabel; `#isIssueReady` inside `dispatch` re-reads the live issue from projection and enforces it. Do not change labels between filing and dispatch.
- **Self-inflicted race: changing labels on an issue mid-dispatch caused three dispatch failures.** Removing `factory` label broke `isIssueReady`; re-adding it during dispatch updated the projection between triage read and live read, triggering `LiveDispatchStateChangedError`. The original routing WAS correct — the factory label is filtered from routing and source repo takes over.
