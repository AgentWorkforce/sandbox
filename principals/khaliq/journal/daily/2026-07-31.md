# Daily

## Shipped

- AR-448 implemented and opened as relay PR #1402,

  Branch `feat/ar-448-durable-workspace-identity`. Not merged — merge is
  Khaliq's gate.

## Learned

- The durability bug had one root cause, not several. `node up` resolved a
  workspace from an explicit key, then the project pin, then nothing — so a
  start with no pin fell through to the broker, which mints a fresh
  messaging-only workspace (`startup_single_session_set_from_sources` in
  `crates/broker/src/relaycast/auth.rs`). The machine-global canonical
  workspace, the one `agent-relay workspace switch` sets, was never consulted.
- Agent identity was never the separate problem it looked like. Relaycast
  returns the existing agent when a name is re-registered in a workspace it
  already belongs to, so a stable workspace is sufficient for a stable Chief
  address. Fixing the workspace fixed the address.
- The failure was silent by construction. A node minting a fresh workspace
  starts cleanly and its resident agent registers successfully; only the
  delivery address changes. Nothing logs an error, which is why it survived
  this long.
- Importing `@agent-relay/cloud` (the package barrel) into broker startup
  broke `doctor.test.ts` by dragging the HTTP/auth surface into its module
  graph. The narrow `@agent-relay/cloud/workspace-key` subpath is the right
  entry for startup-path code.
- The CLI test harness was reading the developer's real workspace store.
  Adding the store fallback made `up` tests pick up — and nearly print — the
  live workspace key. The harness now defaults `AGENT_RELAY_HOME` to an
  isolated temp dir.

## Decided

- Divergence across Relaycast/Relayfile/RelayAuth warns by default and only
  hard-fails under `--require-unified`. Making it fail by default would have
  been a breaking change to every existing caller of `workspace active` for a
  condition none of them currently hit.

## Shipped (later)

- `scripts/factory-control.mjs` gained a `comment` command
  (`npm run factory:comment -- <LINEAR-KEY> <body-file|-> [key]`), closing the
  gap where Chief could create Linear issues and labels but not write a
  checkpoint back to an existing one. Idempotent by body digest, so a retried
  checkpoint reuses its draft instead of double-posting; the comment body field
  is read from the mount's advertised create example rather than hard-coded.
- Fixed the same script's error handling. The workspace mount resolved at module
  top level, outside the try/catch, so any operational failure printed a raw
  Node stack trace and even `badcommand` couldn't report its usage. Argv is now
  validated before connecting, and a connection failure explains itself.

## Learned

- Relayfile provider writeback has been down all session:
  `500 mount_session_failed` on every senses-session mint. It blocks the AR-448
  Linear checkpoint, and it means the new `comment` command's writeback path
  (draft → receipt) is unproven against a live mount — only its argument and
  body validation are verified.
