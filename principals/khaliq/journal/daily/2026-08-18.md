## Learned

- **A shared checkout lags origin/main — and I walked into my own rule.** I told
  Khaliq production was on engine 8.0.1 and that deploying meant "four releases
  of drift including migration 0035." That reading came from my **local**
  relaycast-cloud checkout, sitting on branch `factory/61-join-ticket`, **5
  commits behind origin/main**. `origin/main` pins **8.0.4**, so the real gap is
  a single release. And `0035_agent_token_grace.sql` is present in **both** the
  8.0.4 and 8.0.5 tarballs — added 2026-08-17 by #332, already deployed, not new.
  I raised a production gate on stale data and had to retract it. Verify the ref
  before quoting a version; `origin/main` is not the working tree.
- **Finished work may have no artifact yet.** `relayauth-refresh-500-0818` read
  as idle; attaching showed it had finished — root cause, fixes, passing tests,
  a bogus-token control at 401 — but held **five uncommitted files, zero
  commits, no PR**. "Measure the lane by the artifact" assumes an artifact
  exists. A lane that respects an operator boundary is the *most* likely to park
  without pushing, because it reads "stop" as covering the commit too.
- **Secrets ride in argv, and the reader is other agents.** 15 of 15 agent
  processes carry the live workspace API key and their own `at_live` token as
  plaintext command-line arguments, across both `codex` and `claude` engines,
  all sharing one key. Any lane can `ps` and impersonate any sibling with no
  exploit — which compounds relaycast#311, since the tokens needed to exploit an
  eviction are readable. Filed **relay#1570**. Also found chief's
  `.agentworkforce/relay/connection.json` at mode 644 holding the api_key;
  chmod'd to 600.
- **A single-endpoint probe cannot clear a shared dependency.** I called the D1
  fault "stopped reproducing" off 30 clean probes of one endpoint while it was
  still failing on `select "status" from "nodes"`.
- **A loose predicate overstated the reclaimable set by 60%.** I reported
  "40,742 empty workspaces" all day. That was the **"no messages"** predicate
  alone, which counts ~15,850 workspaces that **do have registered agents** — a
  quiet workspace is not an abandoned one. Measured with an explicit predicate
  against production: **41,443 total**, **25,014 inert** (no agents, messages,
  files, nodes or usage records), **16,339** of those older than seven days.
  Name the predicate whenever quoting a count that authorises a deletion.
- **The worker vendors its own migrations.** relaycast-cloud applies migrations
  from `packages/relaycast/src/db/migrations/`, **not** from the engine package,
  so an engine bump alone ships code writing to tables that do not exist.
  `scripts/check-engine-migrations-synced.mjs` catches it; it failed my 8.0.6
  bump and I vendored `0036`/`0037` byte-identical to the tarball.
- **Requests are not messages.** I concluded all heavy users were internal from
  all-time message volume; Khaliq challenged it with Tel Aviv and Dulles traffic
  and was right. 188 req/s against ~1,500 messages/24h — the two differ by
  ~10,000x, and request traffic currently has **no attribution at all**.

## Decided

- **Briefs go in files, not `--task`.** Long task payloads kill agents on spawn,
  so `.briefs/<slug>.md` holds the brief and the task is
  `"Read <path> and do exactly what it says."`
- **Attach before judging a lane.** Proposed as harness contract in **chief#60**
  (docs-only, +10/-3 to `docs/skip-spec-v1.md`): a read-only attach is required
  before completing, stalling, releasing or replacing a lane; control-plane and
  artifact metadata are rejected as progress evidence; reads are bounded to
  judgment points and ANSI-stripped. It caught a false positive the same day.

## Evening — one defect underneath most of the day

- **One `token_hash` per agent row is the root cause of the day's silent
  failures.** relaycast stores exactly one (`packages/engine/src/db/schema.ts:63`,
  `.notNull().unique()`) and auth is a lookup on it, so **any** re-registration
  under a name evicts the previous holder with no grace window. Documented in
  **relay#1333** (open since 07-18, trigger unattributed for 4 of 5 cases) and
  **relaycast#311** (open since 08-07): `registerOrRotate` takes over an identity
  on the **name string alone, verifying nothing**, while `agents.register` and
  `strict: true` correctly refuse. relay#1546 shipped a broker-side guard in
  v11.7.1 and does **not** cover this. It explains the lane that died at 11:48,
  sf-mini being unable to confirm any spawn, and Chief's own token dying **five
  times in twenty minutes** — each recovery a `register_agent` call that may
  itself be an eviction. Staffed as `relaycast-311-identity-0818`, scoped to a
  written proposal only: Khaliq must first decide whether a name collision is
  **recovery or attack**, because the server says one and the CLI says the other.
- **Two config hypotheses cost an hour on sf-mini before the error text was
  read.** `--no-spawn` and the inert provider both looked conclusive — one is
  documented as gating spawn, the other says it "deliberately has no spawn or
  release capability" — and removing each changed nothing. The third dispatch
  printed `Last read error: Invalid agent token`. Every health signal was green
  throughout (RUNNING, CONNECTED, online/live, all four `spawn:*` advertised)
  because a node can register and hold a socket while unable to complete an
  authenticated read.
- **`agent-relay update` reports success while updating a different
  installation** (relay#1574): the standalone binary and broker stayed at 11.6.7
  with untouched timestamps while npm went to 11.7.1. The handshake constants
  live in the **Rust broker**, so publishing 11.7.1 never reached the code path
  that mattered; a restart then crash-looped the node on the old 5s x4 budget
  against a 7.4-9.5s backend. Fixed by installing the released
  `agent-relay-broker-darwin-arm64` with a fresh inode. Also **relay#1575**:
  `--state-dir X` writes `connection.json` to `X/state/` while the CLI reads
  `X/connection.json`, so a live node reports `STOPPED` — the reading most likely
  to make an operator restart a healthy node and kill every agent on it.
- **The publish blocker was a real bug, not a stale test.** `cli node down` fired
  four times against an expected three because the EXIT trap re-entered and ran
  cleanup twice — fixed in **relay#1576** with a `CLEANUP_STARTED` guard and
  `trap - EXIT`, leaving the assertion untouched. Three hypotheses of mine were
  wrong (#1568, a #1567 x #1572 interaction, the environment); the lane found it
  by reproducing in the exact CI container.
- **Replay's factory half merged** (`factory#290`) with the seam agreed **in
  writing before either side wrote code**: three keys, no fourth replay id,
  retention as live resolver data rather than a frozen expiry claim, resolver
  authenticated, reference never payload. Remaining work is the relaycast join,
  which is blocked on Relaycast exposing session-metadata lookup and the
  effective retention boundary.
- **Retention becomes a pricing tier** (Khaliq, relaycast#341), superseding the
  three-way replay-retention choice. The engine already supports it —
  `workspaces.retention` per-workspace TTLs where `null` disables pruning — so
  the work is a plan-to-retention mapping, gated on attribution (relaycast#339).
