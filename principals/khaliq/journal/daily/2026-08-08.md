## Learned

- **The dead event feed and the paused webhook queue were one incident, and two
  lanes spent hours hunting a fault that did not exist.** Confirmed with a
  filtered Cloudflare API readback: **`settings.delivery_paused=true` for BOTH
  `webhook-events` and `webhook-events-dlq`**. Wrangler tail on the production
  consumer showed `hop=ingest ok` → `hop=enqueue ok` and **zero `consume` or
  `cloud_web_forward_*` logs** in the same window. **The HTTP 202 was always
  honest — the event was accepted into a paused queue.** So the Relayfile
  projection has been frozen since 2026-08-03 not because delivery broke but
  because delivery was deliberately stopped for the `cloud#2917` containment, and
  `factory triage` returning `found 0 matches` org-wide is a downstream symptom
  of an incident nobody had connected to it.
  **The correlation that found it was arithmetic, not code:** the queue alert
  reported an oldest message age of 6,153 minutes, placing it at ~2026-08-04T04:42Z,
  against a mount `lastEventAt` frozen at 2026-08-03T07:26Z. **Two numbers a day
  apart, in two different alerts, that nobody had put side by side.**
- **Ask what a lane has PRODUCED, never whether it looks alive.** The RA-1/RA-2
  lane held the critical path and produced **nothing in three hours** — no branch,
  no PR, no contract — while a sibling lane sat blocked waiting on its schema.
  Message read receipts told the blocked lane nothing. **A pushed branch is
  evidence; a read receipt is not.** The same check caught it here that caught
  the finn-mini losses yesterday.
- **A stale node row reads exactly like a dead node.** `soc2-ra4-oidc-sponsor`
  reported `barry` offline with `activeAgents: 0` and a heartbeat from
  2026-08-05 — close to barry's `createdAt`, so it had read a creation-era
  snapshot. Direct query returned online, live, **35 agents**, heartbeat seconds
  old. Its *conclusion* (no RA-2 contract exists) was correct; its *diagnosis*
  was not. **Verify a node by querying it by name and reading `lastHeartbeatAt`
  against the clock** — the list lies by omission and by staleness.
- **Production was blind in exactly the way the operator machine had been.**
  `mount_stale` fired **7,245 times** with 24 suppressed repeats on
  `proactive-runtime-worker / production`, severity 8/9. The deployed worker is
  **v129, created 2026-08-07T15:00:34Z**, while `factory#220` — which adds
  `localMountDegraded` and the `eventListener` state — merged
  **2026-08-08T08:54:31Z**. The diagnostic that would have surfaced it postdates
  the running build by about eighteen hours.
- **Load is not distributed and nothing enforces it.** `maxAgents: 0` on every
  node means unlimited. barry carried **35** agents against chief-broker 21,
  sf-mini 20, finn-mini 11 — barry alone holding more than the two minis
  combined, on the oldest broker of the four. `relaycast#308` makes unreported
  load *honest*, but **honest reporting is not scheduling**: nothing consumes it
  to place work.

## Decided

- **The SOC-2 proposal is the plan.** `soc2-architect` (fable) delivered four
  sections to `sales#27` and resolved the credential blocker by design:
  **two-phase grant/finalize, both node-side**, so the worker never holds a
  RelayAuth credential. It **rejected** the `at_live → RelayAuth` exchange
  because that imports `rk_`-rooted Relaycast auth into the trust boundary —
  importing the very hole the programme exists to close.
- **`audit_logs` is disqualified as the ledger** — 2-day default retention
  (`audit.md:552`). New write-once tables with abort triggers instead.
- **`sponsorId` is an arbitrary body string today** (`identities.ts:445`), and
  sponsor fields are PATCH-immutable — so **creation is the single choke point**
  for Hole 1, which is what makes the fix tractable.
