  native RelayAuth delegated mint is unavailable.

  `senses`, `broker` all OK; `integration:github` and `factory` WARN. GitHub
  reports `syncHealthy:false` / `ingressHealthy:false` on both installations
  despite a recent event (19:36Z). Factory has no live instance — both
  registered instances are offline/stopped since 07-23/07-24, so nothing can
  be dispatched today even if an issue were fully labeled.
- **Factory came live later the same evening** and the earlier reading is
  superseded. The doctor gained a `hostedBrain` check (`cloud-factory-brain`,
  active) and now reports `factory` OK; the three legacy instances are still
  offline/stopped/degraded but no longer gate dispatch. Linear-sourced runs
  are active against `AgentWorkforce/cloud` and `AgentWorkforce/relay` on both
  `single` and `team` recipes. Lesson: a doctor reading is a timestamp, not a
  fact — the script itself changed under the resident mid-session.
- **Chief has no relay MCP tools this session, and it is a startup timeout,
  not missing wiring.** The broker passed a correct inline `--mcp-config`
  declaring an `agent-relay` stdio server; `npx -y agent-relay mcp` blew
  through Claude Code's 30s connect timeout, so the session started toolless.
  A restart would likely fix this instance; the durable fix is spawning the
  installed binary instead of npx. Details in `memory/open-threads.md`.
- Senses mount is live and readable across `/linear`, `/github`, `/digests`.
- This repo carries two brains. The tracked top-level `memory/` + `journal/`
  is **Will's** profile from before the `principals/` refactor; the active
  brain per `chief.config.json` is `principals/khaliq/`. Read the former,
  never write it.
- Platform truths worth carrying over from Will's profile: never dump raw
  `env` (length-based redaction missed a 35-char `br_` key), and never start
  the node from inside a Claude Code session (`CLAUDE_CODE_CHILD_SESSION=1`
  propagates and silently disables transcript persistence — any clean-env
  path such as `npm run chief` is fine).
- The Cloud dashboards answer infrastructure questions, not Chief
  conversations: Fleet shows the current node/socket/handler roster, Factory
  shows instances and runs, and `npm run chief` remains the interactive front
  door (`chief:view` is read-only).
- A fresh Factory `lastReceivedAt` does not imply liveness. Hosted orchestration
  was writing meaningful run/failure events without `instance.heartbeat`, so
  Cloud showed “Latest check-in: Just now” and “OFFLINE” simultaneously.
- Factory dispatch failures were caused by a field mismatch:
  orchestration supplied the deployed user while the Fleet emitter looked for
  a differently named field and fell back to a placeholder owner. The fix is
  paired with a readiness gate and quarantine so correcting identity cannot
  accidentally launch the old AR-282/306/328 records.
- A second dispatch failure was transport-level: raw Relaycast action
  invocation rejects a workspace key. The supported workspace agent-spawn API
  returns a provider invocation ID, so Factory must persist both its
  deterministic ID and that provider ID for reconciliation.
- RelayAuth's production D1 is at its 10 GB ceiling. Live worker logs prove
  token persistence fails with `Exceeded maximum DB size`; retention is
  enabled but the 90-day audit set does not fit the database. The existing
  #2857 rebuild/data-policy gate requires explicit operator authorization, so
  no direct database cleanup or cutover was performed.
- Factory control now prefers Chief's valid cached senses credential before
  minting a new one. This keeps status/read paths working during a token-mint
  outage and avoids creating retry identities, but provider writeback still
  blocks correctly until RelayAuth capacity is restored.
